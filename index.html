zaentrum schemas

Published contracts for the zaentrum media platform. Every schema URL below is its own $id, is served as JSON, and is stable for its major version. The library schemas are the exception: v1 and v2 are both drafts until a platform service adopts them, and every change is listed in the repository README.

Library storage — v2

JSON Schema (draft 2020-12) for the on-storage library, where the database is the working copy and the tree is a written-once record that can rebuild it. Every item is a folder holding item.json, the projected metadata.json, and one record per original, version, package and later fact.

item.schema.jsonThe identity of a movie, series or episode: id, type, reference ids, the title at creation, an episode's numbering, and where the item came from. Written once.
metadata.schema.jsonThe database's texts, image list and storage decisions for the item, projected whole: which version plays by default, how far to trust the reference ids, and where the item sits in each episode ordering. The images sit in metadata/, each named by its own content hash.
source.schema.jsonOne original as it was found: name, size, hashes, container, every stream, how the file's own name numbered what it holds, and the essence a package can fail to carry.
version.schema.jsonWhat a version is: edition, presentation, runtime, completeness, chapters and detected ranges, the sources it was made from, and the originals kept in its folder.
package.schema.jsonWhat the packager produced: renditions, subtitles, trickplay, trailers, the recipe, the losses and the checksums that prove a copy of it is complete.
event.schema.jsonA fact that arose after the records were written, applied over them in order: an original deleted, a version removed, a package superseded, a source removed, a note.
defs.schema.jsonShared definitions.

Validate a tree with python tools/validate-library-v2.py <dir> from the repository.

Library storage — v1

JSON Schema (draft 2020-12) for the on-storage library, where storage is the source of truth and databases are caches rebuilt from it. Every item is a folder holding manifest.json and metadata/metadata.json.

manifest.schema.jsonThe entry point of a movie, series or episode: identity, reference ids, playback fields, and every version with what its original contained and what its package lost.
metadata.schema.jsonEvery text and image of an item. The images sit next to it in metadata/.
defs.schema.jsonShared definitions.

Validate a tree with python tools/validate-library.py <dir> from the repository. The format is described in the wiki.
